# Zence brand assets

Everything here is generated by [`build.py`](build.py) from the artwork in
[`source/`](source), and checked back against it by [`verify.py`](verify.py).
**Edit the measurements in `build.py`, never the SVGs** — they are outputs, and
a hand-edit is silently lost on the next run.

```bash
python3 brand/build.py      # regenerate every asset
python3 brand/verify.py     # diff the vectors against the artwork, exit 0/1
```

## Which file

| | |
|---|---|
| [`zence-mark-on-light.svg`](zence-mark-on-light.svg) | The mark for light backgrounds — dark ink |
| [`zence-mark-on-dark.svg`](zence-mark-on-dark.svg) | The mark for dark backgrounds — white ink |
| [`zence-icon.svg`](zence-icon.svg) | Square, transparent, flips with `prefers-color-scheme`. Shipped as the site's favicon |
| [`zence-icon-field.svg`](zence-icon-field.svg) | Square on an opaque ink field, for anywhere transparency composites badly |
| [`zence-social.svg`](zence-social.svg) | 1200×630 link preview |

Two rasters are generated into the web app because their consumers cannot read
SVG: `apps/web/app/apple-icon.png` (iOS ignores an SVG touch icon) and
`apps/web/public/social-card.png` (no scraper renders SVG).

The site's header logo is [`apps/web/components/mark.tsx`](../apps/web/components/mark.tsx)
— the same geometry, painted from `--color-brand-*` so it follows the theme
toggle rather than only the operating system.

## Colour

|  | On light | On dark |
|---|---|---|
| Ink | `#29333D` | `#FFFFFF` |
| Accent | `#86A967` | `#86C34A` |

The two greens differ in the supplied artwork and are kept that way: a green
needs more chroma to hold its weight against a dark field.

These are the *mark's* colours and are deliberately not the site palette's. The
site uses green to mean **allow**; a logo that borrowed that green would be
saying something it does not mean.

## What was normalized, and what was not

The two exports disagreed slightly, so `build.py` had to choose. Recorded here
because "the logo is 2px different from the file you sent" should be an
explanation, not a surprise:

**Averaged**, being export noise — bar height differed by 2px in 81, and tab
centring by 1.5px in 944.

**Reproduced as drawn**, because both exports agree and that makes it artwork:
the bottom tabs are shorter than the top ones; there is an unpaired upward tab
at the bottom bar's right end, so the mark is not rotationally symmetric; and
the diagonal is a trapezoid rather than a parallelogram.

The diagonal is also not one stroke — it is two of the same slope, offset, with
the accent laid exactly across the break. Fitting it as a single edge leaves a
9px residual; fitting it as two puts each inside a pixel. For a tool whose
subject is interrupting something mid-flight, that severed diagonal is the idea,
and drawing the obvious single stroke would have quietly destroyed it.
